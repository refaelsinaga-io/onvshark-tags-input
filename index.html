onvshark-tags-input

Lightweight, zero-dependency tags input for any web project. Attach it to a text input by id: free tags, or pick-only tags from a local list or a search URL.

API Reference

const tags = OnvTagsInput.init(id, options)
#ParameterTypeDescription
1 id string | HTMLInputElement Input id ('kota' or '#kota') or the element
2 options object Optional, see the options table below

Options

KeyTypeDefaultDescription
sourcearray | stringnullEmpty = free tags. Array = pick from local list. String URL = search via fetch(url + query)
creatablebooleanfalseWith a source: text not in the list can become a new tag
maxnumber0Maximum number of tags, 0 = unlimited
separatorstring','Separator used in the input value

Modes

sourceBehavior
emptyFree tags. Enter or comma adds a tag. Leftover text on blur becomes a tag.
arrayLocal list. Typing filters the list, pick with click or arrows + Enter. Text not in the list is rejected. The array is read live.
string URLServer list. Same as array, the list comes from fetch(url + text) while typing (250 ms delay).
+ creatableList + new tags. No exact match shows + Tambah "text". New tag value = its text, chip gets .onvs-tagsinput-tag-new.

Source items can be strings or { value, label } objects. The input stores the value, the chip shows the label. A URL must return that array as JSON, or { data: [...] }.

Return

Property / MethodDescription
getTags()Array of values, e.g. ['1', '5'] (a new tag's value is its text)
getNewTags()Array of texts of new tags (creatable)
setTags(list)Replace all tags. Values or { value, label }
add(tag)Add one tag. Returns false when duplicate / full / empty
remove(value)Remove a tag by value
elementWrapper element (.onvs-tagsinput)

Code Examples

Free tags

OnvTagsInput.init('kota')

Local list from Blade

OnvTagsInput.init('kategori', { source: @json($kategori) })
// [{ value: 1, label: 'Berita' }, { value: 2, label: 'Olahraga' }, ...]

Search URL

OnvTagsInput.init('provinsi', { source: '/api/provinsi?q=', max: 3 })
// Laravel route
Route::get('/api/provinsi', function (Request $request) {
    return DB::table('provinsi')
        ->where('nama', 'like', '%' . $request->q . '%')
        ->limit(20)
        ->get(['id as value', 'nama as label']);
});

Edit form with a URL source

const provinsi = OnvTagsInput.init('provinsi', { source: '/api/provinsi?q=' })
provinsi.setTags(@json($terpilih))  // [{ value: 3, label: 'Banten' }]

Save in Laravel

$ids = array_filter(explode(',', $request->kota));

Listen for changes

document.getElementById('kota').addEventListener('change', e => console.log(e.target.value))

The input's own classes (e.g. form-control) move to the wrapper. An input without classes gets .onvs-tagsinput-plain.

The original input is hidden, so a theme's .form-control:focus does not apply. Add a focus style yourself:

.onvs-tagsinput.form-control:focus-within { border-color: #86b7fe; box-shadow: 0 0 0 .25rem rgba(13, 110, 253, .25); }

Behavior

  • The original input is hidden and always holds the value ("a,b,c"), so a normal form submit sends it.
  • Every tag change fires change on the original input.
  • One instance per input. Calling init again returns the existing instance.
  • Duplicate values are ignored. Values containing the separator are rejected.
  • Backspace in an empty field removes the last tag. Esc closes the list.
  • Enter in an empty field is not blocked, so the form can still submit.
  • List mode: picked items leave the list. Unpicked text is dropped on blur.
  • add() / setTags() from code are not checked against the list.
  • A required input needs manual validation, since it is hidden.
  • disabled / readonly inputs are not supported yet.
